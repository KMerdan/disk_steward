# Disk Steward 1.4.0

## A quiet guard: no background file scanning, and the folders that changed are named

Version **1.4.0 (build 11)** supersedes 1.3.0. Disk Steward no longer scans
files in the background. It keeps watching free space, keeps a history of it,
warns before you run low, and names the folders that changed, all at almost no
cost. On the maintainer's Mac it averaged **0.06% of one core** over an hour
while idle.

- **No background file scanning.** When idle, the app takes a capacity sample
  every few minutes and reads the macOS file-system change journal. It walks
  no folder, writes no file database and runs no retention.
- **Capacity history.** Each sample goes to a small history file: one sample
  per 5 minutes for a week, and one per hour for a year. A year of history for
  one disk takes about 600 KB. `get_storage_summary` reports it.
- **A free-space reserve.** "Keep at least N GiB free" replaces the
  percentage threshold. Its suggested value is derived from your old
  threshold. You get one notification when free space stays below the
  reserve on two samples in a row. It does not repeat until free space has
  recovered. The board shows how far you are above or below it.
- **Which folders changed.** Changes inside your review scopes (formerly the
  watched folders) are recorded from the FSEvents journal, by project or
  build-output folder, without walking the disk.
  - Changes made while the Mac slept or the app was closed are replayed at
    launch.
  - `explain_growth` answers with the capacity change and the changed
    folders.
  - Gaps such as the journal starting, a journal reset or dropped events are
    stated, never shown as "no change".
  - Folder sizes are not measured in this release.
- **Your old evidence is kept, unmodified.** On first launch the evidence
  database is moved, byte for byte and with its log, to
  `legacy/evidence-<date>.sqlite` in the app's support folder. Nothing reads
  it or adds to it.
  - **Export** it from **Settings › Legacy evidence**.
  - **Delete** it there; it moves to the Trash after you confirm.

### What changes for agents

- **`get_storage_summary` and `explain_growth`** answer as described above.
- **`list_current_consumers`, `get_provenance`, `find_cleanup_candidates`,
  `get_task_impact` and `get_evidence_lifecycle`** answer `detail_unavailable`
  ("file-level scanning is retired"). A bounded folder review will bring
  file-level answers back in a later release.
- **`export_evidence`** exports the legacy evidence. A legacy database too
  large for an inline answer returns `legacy_export_too_large`; export it from
  Settings instead.
- **Session registrations** are kept in memory. Register again after a
  relaunch.

### Going back to 1.3.0

Quit Disk Steward first. Then run the
[`restore-legacy-evidence`](https://github.com/KMerdan/disk_steward/blob/v1.4.0/Scripts/Distribution/restore-legacy-evidence)
script from this release's source with `zsh restore-legacy-evidence`, and
install 1.3.0 only after that.

The script checks every file against the hash recorded when it was moved, and
then renames it back. If you install 1.3.0 without running it, 1.3.0 starts an
empty database and resumes scanning.

### Release checks

The universal Apple Silicon / Intel app supports macOS 13 or later. It is
Developer ID signed, notarized by Apple and stapled. The exported app and the
app unpacked from the ZIP both pass signature, notarization-ticket,
Gatekeeper, entitlement and installed-launch checks.

The released source passed 658 Swift tests (8 intentional skips, 0 failures)
in an isolated, supervised run. The move, export and rollback were rehearsed
on a copy of a real 405 MB evidence database. On the maintainer's Mac the
installed move was byte-identical.

### Upgrade

```sh
brew update
brew upgrade --cask disk-steward
```

### New installation

```sh
brew trust KMerdan/disk-steward
brew tap KMerdan/disk-steward
brew install --cask disk-steward
```

Trust the third-party tap only if you intend to accept its current and future
casks.
