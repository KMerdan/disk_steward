# Disk Steward 1.5.0

## Review Storage: build outputs, environments and caches as whole objects, ranked, in about a minute

Version **1.5.0 (build 12)** supersedes 1.4.0.

Disk Steward can now review a folder and say where reclaimable space actually
is. Build outputs, environments and caches are counted as whole objects, and
nothing is stored file by file. On the maintainer's Mac, `~/localGit` took
**54 s** to review cold and **45 s** warm, and found **62.68 GB worth
reviewing in 2,000 items**. The sizes match `du`.

### Review Storage

Open it from the menu-bar menu (**Review Storage…**, ⌘R) or from the status
board.

- **Choose a scope:** one of your monitored folders, or the tool caches
  you opted into.
- **One bounded walk.** The review stops at 120 s or 5 million entries. A
  review that stops early is marked partial and names what it did not cover.
- **Whole objects.** `node_modules`, `target`, `.venv`, DerivedData and
  similar folders are measured as single objects. Nothing inside them is
  listed or stored.
- **Never offered for review:** repositories, git internals, and files git
  tracks.
- **Ranked by reclaim value.** Items are ordered by size, by how long their
  project has been idle, and by how costly they are to recreate. At most
  2,000 items are shown, grouped by project.
- **Evidence for each item:**
  - why it may be disposable, and reasons to keep it;
  - how to recreate it, for example `pnpm install` or `cargo build`;
  - the owning tool's own cleanup command, shown as text and never run;
  - **Reveal in Finder** and **Copy Review Brief**.

  Nothing is declared safe to delete, and Disk Steward still deletes
  nothing.

### Cache review

**Settings › Cache review** lists ten known developer caches, each off until
you turn it on:
- uv, npm and the pnpm store;
- `~/Library/Caches`;
- CoreSimulator, Xcode DerivedData and Xcode Archives;
- Ollama, Docker Desktop's disk and the act cache.

Caches not found on your Mac are disabled.

### Measured growth

When used space grows by your growth threshold (5 GiB by default), Disk
Steward measures the objects inside the folders that changed and attributes
the growth to them. `explain_growth` reports:
- each object's measured change, and how it was measured;
- the part of the change that no measured object explains.

### What changes for agents

The MCP helper now offers ten read-only tools:

| Tool | Answers |
| --- | --- |
| `get_storage_summary` | Capacity, the free-space reserve and history (unchanged) |
| `get_health` | **New.** Store sizes against their caps, the change journal, and the latest review of each scope |
| `explain_growth` | Capacity change, changed folders, and now **measured growth** with the unexplained remainder |
| `list_review_items` | **New.** The latest review of a scope, with the same numbers and states as the window |
| `get_review_item_evidence` | **New.** One item's reasons, commands and a live check |
| `list_largest_objects` | **New.** The largest measured objects |
| `measure_path` | **New.** One folder inside your scopes or opted-in caches, within 15 s and 500,000 entries |
| `list_active_agent_sessions` | Registered sessions (unchanged) |
| `get_task_impact` | **Works again.** The folders a session changed. Sessions are kept across relaunches |
| `export_evidence` | **Changed.** It now exports the current evidence: capacity change, changed folders, recent reviews and growth attributions. Export the legacy database from Settings |

**Removed tools:** `list_current_consumers`, `get_provenance`,
`find_cleanup_candidates`, `get_evidence_lifecycle`, and the
`list_active_writers` alias. They answered "file-level scanning is retired"
in 1.4.0.

**Codex users.** If you installed the Codex integration with
`Scripts/Integration/install`, run it again from this release's source.
Codex only offers the tools listed in `enabled_tools`, and the old list
names retired tools. The script replaces only its own block and keeps a
backup. Then start a new Codex task.

**Claude Code users.** Start a new session.

### Going back to 1.4.0

1.5.0 does not change the store's format, so you can go back without a
script. Quit Disk Steward, then install 1.4.0 from the
[v1.4.0 release](https://github.com/KMerdan/disk_steward/releases/tag/v1.4.0).

1.4.0 ignores the new review and growth files. Your legacy evidence is
untouched.

### Release checks

The universal Apple Silicon / Intel app supports macOS 13 or later. It is
Developer ID signed, notarized by Apple and stapled. The exported app and the
app unpacked from the ZIP both pass signature, notarization-ticket,
Gatekeeper, entitlement and installed-launch checks.

The released source passed 727 Swift tests (11 opt-in skips, 0 failures) in
an isolated, supervised run. The same build was installed on the
maintainer's Mac before release:
- `~/localGit` reviewed in 54 s cold and 45 s warm, with object sizes equal
  to `du`;
- seven opted-in caches matched `du` within 5%;
- a synthetic million-file tree reviewed in 6.6 s;
- the app idled at **0.16% of one core** over an hour;
- every agent tool answered. In the isolated run, each answer stayed under
  1 MiB with every table full.

### Upgrade

```sh
brew update
brew upgrade --cask disk-steward
```

### New installation

```sh
brew trust KMerdan/disk-steward
brew tap KMerdan/disk-steward
brew install --cask disk-steward
```

Trust the third-party tap only if you intend to accept its current and future
casks.
