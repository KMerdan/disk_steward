# Disk Steward 1.3.0

## Agents always get an answer, and a scan that cannot finish stops itself

Version **1.3.0 (build 10)** supersedes 1.2.3. It fixes the failure where the
Claude Code, Codex and other agent integrations stopped working with
"Lifecycle metadata exceeds the summary budget". It also stops background file
scanning from running indefinitely on large folders.

- **Agent tools keep answering.** Lifecycle summaries list the newest coverage
  gaps together with their totals, instead of refusing once the history grows
  large. Coverage is still judged from every gap, so a shortened list never
  claims complete coverage.
- **Free space always answers.** The storage summary, the helper's
  self-check and the status board report live capacity even when the
  evidence database is refused, corrupt, locked or over its limit. The
  response states which detail is unavailable and why.
- **A scan that cannot converge stops.** Detailed file scanning stops when it
  keeps re-walking without making progress, when storage refuses it
  repeatedly, or when it runs too long. The stop stays in place across
  relaunches, and the status says why and what to change. It retries after
  24 hours, or sooner if you change the watched folders or the database
  limit. Volume capacity monitoring continues throughout. While a scan is
  stopped, file changes no longer trigger extra samples: on the
  maintainer's Mac the app idles at about 0.4% of one core.
- **Build output is scanned as whole objects.** Folders such as
  `node_modules`, `target`, `.build`, `.next` and Python environments are
  recognized from project evidence and are no longer walked file by file.

The universal Apple Silicon / Intel app supports macOS 13 or later. It is
Developer ID signed, notarized by Apple and stapled. The exported app and the
app unpacked from the ZIP both pass signature, notarization-ticket,
Gatekeeper, entitlement and installed-launch checks.

The released source passed 618 Swift tests (7 intentional skips, 0 failures)
in an isolated, supervised run.

### Your evidence database is upgraded in place

On first launch, 1.3.0 migrates the evidence database from schema 14 to
schema 15. **Versions 1.2.x cannot open a schema-15 database.** If you might
return to 1.2.3, first quit Disk Steward and copy
`~/Library/Application Support/Disk Steward/evidence.sqlite` to a safe place.
Capacity monitoring keeps working whatever state the database is in.

### Upgrade

```sh
brew update
brew upgrade --cask disk-steward
```

### New installation

```sh
brew trust KMerdan/disk-steward
brew tap KMerdan/disk-steward
brew install --cask disk-steward
```

Trust the third-party tap only if you intend to accept its current and future
casks.
