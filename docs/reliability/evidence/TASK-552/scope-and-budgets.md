## Behavior added

- **Effective scope at query time.** `EvidenceQueryScope` carries the current watched roots and exclusions as normalized paths and builds a bound-parameter SQL predicate (`path = ?` or exact prefix via `substr`; no LIKE wildcards). The store applies it to current consumers, cleanup candidates, growth aggregate and page, provenance identity/current-state/event selection, and task-impact candidates; the exporter applies it to current state, aggregate, events, rollups and claim payloads. The backend obtains the scope per request from `queryScopeProvider`; the app wires it to `MonitoringSettingsStore` on the main actor. A policy change is visible immediately and the next scan reconciles retained detail; hidden rows are never reported as deleted. Pages carry `scope` (`applied`, hashed `scope_version_id`, root/exclusion counts, `hidden_by_scope_count` for current-state reads) and `get_evidence_lifecycle` reports `effective_scope` with `matches_latest_scan` against the latest observation's scope version.
- **Missing evidence is explicit.** `coverage` becomes `none` only where a `complete` claim had no completed observation and no rows; an active scan keeps `partial`. Pages add `state_age_seconds`. Missing session evidence remains a typed `session_unavailable`.
- **Budgets before materialization.** Every paged tool clamps the requested limit to what the response byte ceiling (default 1 MiB) can hold for its worst-case item size before the store reads, reports `budget` (`row_limit_requested`, `row_limit_applied`, `response_byte_ceiling`), and refuses an encoded response above the ceiling with nonretryable `response_too_large` instead of a partial page. Task-impact admission rows/bytes are injectable for tests and default to the product values.
- **Honest identity bound.** Provenance resolves at most 100 file identities; a 101st sets `identity_limit_reached` and a limitation instead of silent truncation.
- **Revision-bound session cursors.** Active-session pages bind their offset to the ordered registration set; membership or order changes return nonretryable `cursor_expired`.
- **Typed registry errors.** Duplicate session or process registrations are `session_conflict`; unknown or stale registrations and validation failures are `invalid_registration`; proof mismatch is `permission_denied`. None degrade to the generic retryable `request_failed`.
- **Attribution no longer lost to time-base rounding.** A retained claim keeps its event dates as reference-date seconds while the store returns the same instant from Unix seconds; converting between the bases moves roughly a quarter of wall-clock values by one binary digit. `ProvenanceEngine.taskAttribution` and `ProvenanceChronology.isValid` compared those exactly, so `get_task_impact` intermittently reported an attributed session as `unknown` with zero totals. Both now tolerate one microsecond of representation error and nothing more; endpoints are never reordered and a genuinely different observation is still rejected.

## Verification boundaries

Raw events inserted without an observation have no occurrence bounds and are not task-impact candidates by design; the cardinality test proves the admission refusal with a 300-row budget on the same code path the 100,000-row / 8 MiB product default uses, not that the default is correctly sized for every store. Wall-time assertions are coarse (under 60 s for the whole composition); SQLite step counts and RSS were not measured. Worst-case item sizes for the pre-read clamp are engineering estimates checked by the post-encode ceiling, not proofs. The scope predicate compares normalized paths, so a symlinked root configured under one spelling and scanned under another is not matched. Exports hide out-of-scope claims after decoding each payload, so an export over a very large claim table still reads every row before filtering.
